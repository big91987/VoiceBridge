# VoiceBridge

在远程桌面场景下，把本机麦克风变成远端的「语音输入」。

按住一个键对着本机说话 → 语音在本机被识别成文字 → 文字经剪贴板送到远端 → 在远端光标处自动粘贴。

远端不需要装任何东西，不需要麦克风，也不需要模型。

---

## 它解决什么问题

用 UU 远程控另一台 Mac 时，几乎没法好好打字：

- UU 的 **Mac 被控端不支持麦克风上行**，只有「远控 Windows」时控制端麦克风才生效
- 远端机器上没有顺手的语音输入
- 想把手机上的语音输入体验搬到桌面，UU iOS 版又装不进 Mac

VoiceBridge 只补「说话」这一环，画面继续由 UU 负责。

## 工作方式

```
[本机 MacBook Air]                          [远端 MacBook Pro]
按住空格
   ↓
合成 Control → 唤起豆包语音输入
   ↓
豆包识别 → 文字落入浮窗
   ↓
写入本机剪贴板
   ↓  ← UU 远程「同步剪贴板」自动传输 →
                                        Cmd+V 粘贴到光标处
```

## 环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | macOS 12+（开发验证于 14.7.6 arm64） |
| 输入法 | 豆包输入法，**语音触发键设为 Control** |
| 远程工具 | UU 远程，**开启 `操作 → 安全 → 同步剪贴板`** |
| 权限 | 辅助功能、输入监控 |

两台机器登录同一 UU 账号，本机连上远端即可。剪贴板同步由 UU 提供，本项目不做传输。

## 安装

1. 下载 `VoiceBridge-1.0.dmg`（或自行构建，见下）
2. 双击打开，把 VoiceBridge 拖进 `Applications`
3. 首次启动会被 Gatekeeper 拦（本地 ad-hoc 签名、未公证），**右键 → 打开**，或执行：
   ```bash
   xattr -d com.apple.quarantine /Applications/VoiceBridge.app
   ```
4. 启动后，「系统设置 → 隐私与安全性」里勾选 **辅助功能** 和 **输入监控**
5. 菜单栏出现 🎙 图标即就绪

## 使用

1. 按住**空格**（超过 0.35 秒才开录，短按仍是正常空格）
2. 说一句话
3. 松开

松开后约 0.9 秒，文字自动粘到当前光标处。屏幕底部会浮出一个小窗，显示识别到的内容，你可以先看一眼再让它粘。

全屏 UU 状态下也能触发。

## 配置

两种方式，共用同一份配置，位置在用户主目录（不在项目目录里）：

```
~/.voicebridge/config.yaml
```

**方式一：菜单栏点选**（立即生效并写回文件）

| 菜单项 | 可选项 |
|---|---|
| 触发键 | 空格 / Tab / 回车 / Esc / 分号 / 逗号 / 句号 / 反引号 / F13 / 右侧 Command / 左侧 Shift |
| 唤起豆包的键 | 左 Control / 右 Control / 左 Option / 右 Option / F13 / F5~F9 |
| 按住时长 | 200 / 300 / 350 / 500 / 800 ms |

**方式二：手改 YAML**（保存后 1 秒内自动重载，不用重启）

```yaml
# 49=空格  59=左Control  62=右Control  58=左Option  61=右Option
# 54=右Command  56=左Shift  48=Tab  36=回车  53=Esc  105=F13
triggerKeyCode: 49      # 触发键
doubaoKeyCode: 59       # 唤起豆包的键
armDelay: 0.35          # 按住多久才开录（秒）
clipboardWait: 0.85     # 写剪贴板到按 Cmd+V 的等待（秒，给 UU 同步留时间）
```

两个必须注意的点：

- **「唤起豆包的键」必须和豆包输入法里设置的语音键一致**，否则唤不起来。
- **触发键别选修饰键**（如右 Command）。按住 ⌘ 时系统物理修饰状态常驻，合成的按键会被污染，这是开发中实测踩过的坑。

## 已知限制

- **在 UU 远端输入框里按触发键，会有一个空格漏到远端**。远控软件在底层拿走了按键，这一层拦不住（见实现要点 5），只能保证「能唤醒」，多出来的空格要自己删。
- 全屏 UU 连续使用时偶发粘贴延迟，唤醒和识别都正常（剪贴板已写入），失败点在「激活 UU → Cmd+V」的时序或 UU 剪贴板跨网同步延迟。
- 松手到粘贴约 0.85 秒以上延迟，取决于跨网 RTT（实测 400ms~1.1s）。
- 按住触发键期间键盘的自动重复可能漏一个空格到远端。
- 短按（不足按住时长）不会触发录音，也不会产生空格。
- 未做签名公证，每次重新编译 ad-hoc 哈希会变，系统权限可能需要重新授权。
- 未做开机自启。

## 实现要点

几个绕不开的坑，写在这里省得后来人重踩：

**1. 事件监听必须彻底销毁，不能只是禁用**

只要自己的 `CGEventTap` 还挂在系统里（`defaultTap` / `listenOnly` 都算，`CGEvent.tapEnable(false)` 也不够），合成的 Control 事件就到不了豆包输入法，录音条不会出现。必须 `CFMachPortInvalidate` 彻底销毁，合成才能生效。

**2. 唤起豆包的键只能合成，不能靠物理按住修饰键**

豆包判定依据是系统物理修饰状态。手指按着 ⌘ 时，合成的 Ctrl 会变成 ⌘+⌃，豆包不认；伪造「⌘ 松开」又会让按键轮询误判松手。

**3. 剪贴板是这条链路的传输层**

UU 自带双向剪贴板同步，本项目完全不碰网络，只负责把文字放进本机剪贴板、再在远端按 Cmd+V。等待时间必须给够，跨网同步比想象中慢。

**4. 触发键的自动重复会漏字符**

按住触发键期间监听器处于销毁状态，系统的按键重复会直接进入前台。当前版本靠「开头结尾剥标点」兜底。

**5. 远控软件会在底层先一步拿走按键，必须用双通道**

实测结论：在 UU 远端输入框里按空格，`CGEventTap` **完全收不到事件**（系统里也查不到 UU 注册的事件监听），但 `IOHIDManager`（公开的 HID 监听）**能收到**。说明远控软件在比 CGEvent 更低的层就把按键读走并转发了。

因此触发用了两条通道：

| 通道 | 能否看到 UU 里的按键 | 能否拦截 |
|---|---|---|
| `CGEventTap`（会话层） | ❌ | ✅ |
| `IOHIDManager`（HID 层） | ✅ | ❌ |

上层能拦就拦（本机场景空格被正常吞掉，不会多空格）；底层只做「感知」，看到触发键按下就发起录音，作为兜底。两条通道用 0.3 秒时间窗去重，避免同一次按键被触发两次。

**为什么不在底层也拦掉**：`IOHIDEventSystemClient` 的过滤接口（`RegisterEventFilterCallbackWithPriority`）和事件回调实测**注册成功但永不触发**——这类事件监控/过滤需要开发者证书里的私有 entitlement，普通签名拿不到。`CGEvent` 侧的 HID 层 tap 同样收不到被消费后的事件。所以「同时拦住且不漏」在本机做不到。


## 开发

```bash
./build.sh
```

产出：

| 产物 | 路径 |
|---|---|
| App | `VoiceBridge.app` |
| 安装包 | `output/VoiceBridge-1.0.dmg` |

`output/` 与 `VoiceBridge.app` 已在 `.gitignore` 中，不进仓库。

运行调试：

```bash
: > /tmp/vb.log
(open -a ./VoiceBridge.app --args 2>/dev/null; nohup ./VoiceBridge.app/Contents/MacOS/VoiceBridge >> /tmp/vb.log 2>&1 &)
tail -f /tmp/vb.log
```

判定成功必须同时出现 `[诊断] 豆包录音条: 已出现` 和 `[文本] <非空>`；只有 `[合成] ... down` 不代表成功。

确保只有一个实例在跑：

```bash
ps -eo pid,comm | grep -i voicebridge
```
